# preview.3 安装与测试清理修复

## 问题是什么

目录链接像一个指向旧插件目录的入口。旧版加载测试把源码目录链接到临时 profile，再递归删除临时 profile；旧版安装器升级时也递归删除旧链接。

在本次验证的 Electron 43.0.0 / 内置 Node 24.17.0 中，这样会删除链接指向的目录内容。`ELECTRON_NO_ASAR=1` 未消除问题；独立 Node 24.22.1 未复现。因此此前独立 Node 下全套测试通过，不足以证明 DSH 自带运行时下清理安全。这不是所有 Node 24 都会发生的结论。

这不属于记忆算法错误，但可能导致插件源码或旧安装文件丢失，不能仅凭面板能运行就判定旧包适合安装发布。

## 本次修改

- 测试只使用发布白名单文件构成的独立副本。清理时先识别并 unlink 链接，只移除空目录；不对含链接的目录使用递归 rm。
- 安装时先准备新链接，旧入口暂存到同目录备份，再切换登记。成功后只 unlink 旧链接；真实旧目录保留。失败时尝试恢复旧链接与登记。
- 可用新安装器的 `-Plugin` 参数切回保留的旧目录，不调用旧安装器。
- 包装器测试在 Electron 环境下使用 node.cmd。直接启动 GUI exe 时 PowerShell 可能未等待，导致退出码空值，属于原测试调用方式不准确。

## 如何核验

`node --test tests/*.test.mjs` 包含旧源码保留、嵌套链接、回退、记忆和桥接配置保持不变的隔离测试。请同时在独立 Node 和 DSH 自带的 node.cmd 环境运行，不能只测一种。

真实宿主还需按 README 设置 `DSH_HOST_MODULES`，运行 `tests/real-host.mjs`、`tests/real-loader.mjs`、`tests/real-cordis.mjs`。这些测试使用合成数据，不替换用户正在运行的 DSH 插件。

2026-11-01 本机结果：独立 Node 24.22.1 与 DSH Electron 43.0.0 / Node 24.17.0 两种运行时各通过 141/141 项测试；上述三个真实宿主脚本均退出 0。加载测试使用隔离副本且清理后原包完整。此前 Electron 下包装器的单项失败已修正为真实 shim 调用并通过。

这是本地预览修正版。实际安装前保留旧源码并备份正在使用的记忆文件；宿主版本和第三方插件组合仍需按本机情况验证。
